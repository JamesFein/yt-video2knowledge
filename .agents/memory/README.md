# Agent Memory 使用规则

`.agents/memory/` 主要面向 Coding Agent，用来保存从对话和实际操作中提取的经验候选。它是便签和暂存区，不是项目正式知识库；经过验证并需要长期共享的内容应进入 [`docs/`](../../docs/README.md) 或其他更合适的正式入口。

最短的心智模型是：

```text
发现经验 -> 暂存 memory -> 验证与确认 -> 提升到正式位置 -> 标记已处理
```

## 两类 memory

| 类型 | 用途 | 当前示例 |
| --- | --- | --- |
| 规则收件箱 | 暂存用户表达的偏好、纠正、标准和可复用规则，等待审核 | [`captured-rules.md`](captured-rules.md) |
| 主题 memory | 保存范围明确、篇幅短小、尚未成为正式文档的检查项或踩坑提醒 | [`knowledge-site-change-checks.md`](knowledge-site-change-checks.md) |

`captured-rules.md` 中的待审核内容必须标为临时状态。主题 memory 即使已经得到部分验证，也不应成为安全关键操作或当前运行事实的唯一来源。

## 什么应该进入 memory

- 用户明确表达的 `ALWAYS`、`NEVER`、`PREFER` 或 `AVOID` 规则。
- 用户对 Agent 错误的纠正，而且同类错误将来可能再次发生。
- 从真实操作中发现、尚待进一步验证或整理的项目 gotcha。
- 适用范围明确、能在几句话内说清楚的任务检查项。
- 需要跨会话保留，但还不适合写成正式规范的经验。

写入时应尽量记录来源、适用场景和验证日期。规则收件箱还应保留用户原话、提炼后的动作、规则类型和处理状态。

## 什么不应该进入 memory

- 密码、Token、Cookie、凭据内容或其他 secret。
- 进程是否正在运行、临时端口、一次运行结果等瞬时状态。
- 大段原始日志、当前任务计划或只使用一次的中间结论。
- 未验证的猜测，却被表述为必须遵守的规则。
- 可以直接从代码可靠获得、没有额外解释价值的普通事实。
- 已经由正式文档完整覆盖的重复副本。

## Coding Agent 何时读取

Coding Agent 只应在以下场景读取相关 memory：

- 用户表达新规则，或要求捕获、清理、审核规则时，读取 `captured-rules.md`。
- 当前任务与某个主题 memory 的标题和适用范围直接匹配时，读取该主题文件。
- 准备把经验提升为正式规则时，检查来源、验证状态和是否已有重复文档。
- 用户明确要求参考或检查 `.agents/memory/` 时。

不要在每个任务开始时无差别加载整个目录。当前根 [`AGENTS.md`](../../AGENTS.md) 没有链接本 README，因此普通任务不能假设 Coding Agent 会自动发现或读取这里的内容；任务关键规则必须放入可被可靠调用的正式入口。

## 何时升级

一条经验同时满足以下条件时，应从 memory 提升出去：

1. **已验证**：与当前代码、真实数据或部署环境一致。
2. **可复用**：未来的同类任务仍然适用，而不是一次性事故记录。
3. **值得强制传播**：遗漏后可能造成错误、服务中断、安全风险或重复返工。
4. **触发明确**：能够说明谁在什么任务中需要读取和执行。
5. **获得必要确认**：用户偏好、项目规则和共享规范在永久化前已经得到明确确认。

如果结论仍不稳定、适用范围说不清楚或尚未验证，就继续留在 memory，而不是过早正式化。

## 升级到哪里

| 内容 | 正式位置 |
| --- | --- |
| 全项目 Coding Agent 原则和编码标准 | [`AGENTS.md`](../../AGENTS.md) 或其实际源文件 |
| 特定任务下 Agent 必须遵守的约束 | [`docs/agents/`](../../docs/agents/) |
| 当前运维事实、命令和操作步骤 | [`docs/operations/`](../../docs/operations/) |
| 架构选择、替代方案和后果 | [`docs/adr/`](../../docs/adr/) |
| 项目解释、地图和使用指南 | [`docs/guides/`](../../docs/guides/) |
| 个人而非项目范围的长期偏好 | 用户级 Agent instructions |

## 升级后的处理

- 在 `captured-rules.md` 中将条目标记为 `PROCESSED`，并链接最终位置。
- 如果主题 memory 已被正式文档完全覆盖，删除重复内容或将其缩减为指向正式文档的说明。
- 不要长期维护两份内容相同但可能分别变化的权威文本。
- 当 memory 与当前正式文档冲突时，以正式文档为执行依据，同时核验冲突是否说明正式文档已经过时。
- 历史材料若仍有解释价值，应进入 [`docs/archive/`](../../docs/archive/)，而不是继续伪装成当前规则。
