# YouTube 脚本简写提示词系统探索计划

## 目标

本次工作只探索并验证一套更好的“transcript → 简写文章”提示词系统，不改生产摘要链路，不建设通用测试或 API 框架。

最终交付最少数量的脚本类别、分类理由、分类提示词、通用懒提示词、确有必要保留的类别提示词，以及每类 2–3 组原文、历史旧总结和同模型提示词对照结果。

## 样本与分类

- 使用固定随机种子 `20260802`，从 transcript 与旧总结完整配对的数据中分层抽取 60 篇。
- 抽样兼顾日期、字幕来源和原文长度；22 条人工 Meta Summary 仅作偏好弱信号，不进入随机评测集。
- 明显存在 ASR 问题、极短或超长的 transcript 单独作为鲁棒性样本，不计入正常提示词得分。
- 从观点/解释、教程/演示、资讯/市场、叙事/访谈四个候选方向开始，根据提示词实验结果合并到 1–4 类。
- 类别提示词仅在至少 6 篇中达到“4 篇胜出、平均提升 0.25/5、无新增忠实性失败”时保留。

## 成功文章标准

- 文章可独立替代 transcript 阅读，但不要求覆盖所有观点。
- 通常为 600–1,500 中文字，且不得长于原文；短原文不得为凑字数扩写。
- 使用连贯文章，包含一个一级标题、`核心结论` 和 1–2 个有价值的正文模块；二级标题总数不超过 4 个。
- 观点或叙事类围绕一个核心认识和一个最强论据；教程保留必要步骤；资讯允许保留 3–5 条独立信息。
- 案例、金句、限制和行动建议只在原文支持时出现。直接引语必须能在 transcript 中核验并附最近时间戳。
- 说服力只来自清晰结论、决定性证据、具体案例以及因果、对比或转折，不得补充外部事实或虚构背书。

## 同模型提示词实验

所有分类、生成和模型辅助评审均使用 `新的文字简写模型.txt` 中记录的唯一模型。正式比较对每篇保留四种结果：

1. 历史旧总结，仅作真实现状参照。
2. 当前生产提示词使用指定模型重新生成的基线。
3. 新通用懒提示词结果。
4. 新类别提示词结果。

每个初始类别选 6 篇，共 24 篇核心样本；每类再选 2 篇重复生成两次检查稳定性。最多迭代两轮提示词，所有版本和输出均保留。

模型评审只比较忠实性、核心认识、最强论据、案例/金句、文章完整性、简洁性和稳定性。模型评审采用同一模型的无上下文匿名调用，仅作辅助，用户拥有最终裁决权。

## 产物与通过条件

- 大体积样本和生成结果保存在 `data/experiments/summary-prompt-v1/`。
- 分类、提示词、评价标准和结论保存在 `experiments/summary-prompt-v1/`。
- 不覆盖 `data/runs/`，不修改生产摘要代码、Knowledge Site 或 README。
- 24 篇核心样本不得出现忠实性硬失败。
- 最终新提示词相对“当前提示词＋同一模型”的匿名偏好率至少为 70%。
- 8 篇稳定性样本中至少 7 篇两次选择相同核心认识。
- 每个最终类别提供 2–3 组完整对照材料供用户匿名复核。
- 若类别提示不能稳定胜过通用提示，最终只保留通用提示词。
